Summary: RuFlow is built as a local-first Windows desktop AI workspace. Online features remain off by default and transmit information only when you enable them and grant required consent.

1. Local AI Processing & Chat Storage

  • Local Model Inference: Chat conversations processed with your local Ollama installation run on your own Windows PC and are not transmitted to external RuFlow servers. The packaged Windows desktop application includes no cloud AI model SDKs (such as OpenAI, Anthropic, or Google Gemini) and does not transmit local chats to external language-model providers.
  • Local Windows Profile Storage: In desktop installations, RuFlow stores your conversations, workspace settings, documents, and diagnostic logs inside your Windows user profile's local application data folder rather than on developer-operated cloud servers. Access across Windows accounts on the same computer relies on your Windows user-profile permissions, and local application data persists across updates or uninstall until deleted manually. Local Ollama AI models remain in your local Ollama storage directory separately from RuFlow's installer.
  • No Built-In Telemetry or Ad Trackers: RuFlow includes no advertising SDKs, analytics trackers, usage telemetry, or external web-font downloads.

2. Document, Voice & Image Processing

  • Documents, Book Libraries & Presentations: Text extraction for supported attachments (including PDF, Word, Excel, PowerPoint, CSV, plain text, and image file metadata), local textbook library search, and local presentation generation run on your Windows PC. Document content leaves your device only if you send it through an explicit consented online workflow.
  • Voice Features & Audio Recordings: Live online voice readout and browser voice chat controls are disabled and omitted from the packaged Windows desktop application. On the Sing page, voice takes you record or upload are stored locally on your PC in WAV format and can be played, downloaded, or cleared inside the app; however, voice-model training and singing-cover generation depend on external local audio engines not bundled in the core Windows package. If a YouTube link is submitted for song audio extraction where an external singing engine is configured, RuFlow requires explicit consent before contacting YouTube.
  • Image Generation & Safety Status: AI image generation, image editing, and generated-image reuse or export are disabled in the packaged Windows desktop release, and local visual moderation AI models are not bundled or running in the core package. No image-generation prompts or generated images are transmitted to external cloud image services.

3. Diagnostic Logging & Local Error Reporting

  • Local Operational Logs: RuFlow writes rotating diagnostic logs locally inside your Windows user profile log folder for troubleshooting.
  • Built-In Secret & Query Masking: Before writing diagnostic logs or search error summaries, RuFlow automatically masks configured credentials, bearer tokens, web-link user credentials, query parameters, raw HTTP error bodies, and raw search queries.
  • Zero Automatic Crash Telemetry: RuFlow never automatically sends logs, crash reports, analytics, or workspace content to the developer.
  • Local AI Concern Report Drafts: Drafts created through Report AI Content are saved strictly locally on your PC. Nothing is transmitted externally unless you manually export a report file and email it to support.

4. Optional External Search & Web Providers

RuFlow keeps Internet Mode OFF by default. External requests occur only when you enable or trigger an online feature and approve the applicable prompt.

When triggered and consented by you, external data handling differs between general company privacy policies and provider API terms:

  • Tavily: Consented web search transmits your search query and API key. Governed by Tavily's Terms of Service, Privacy Policy, and DPA (AlphaAI Technologies Inc., US). Offers a Zero Data Retention (ZDR) / Zero Query Retention option in eligible account settings (under which queries and results are not stored after completion) and an EU endpoint (API gateway in Germany and search index in France; account, billing, and usage records remain on US systems). Where ZDR is not enabled, Tavily's Platform Terms permit processing and retaining Customer Input to provide and improve services (including AI/ML models), and exact non-ZDR query-log retention days are not published publicly.
  • Brave Search API: Consented web search transmits your query and requested result count. Governed by Brave Search API Terms of Use and the Search API Privacy Notice (distinct from Brave's consumer browser and Brave Leo AI privacy policies). Requests are processed on AWS infrastructure in the United States. Brave retains Search API query logs for up to 90 days for billing and troubleshooting (with Enterprise ZDR options available) and states that no individual user or device identifiers are collected. Standard Search API Terms prohibit API customers from using search results to train AI models unless authorized under specialized data plans.
  • Google Custom Search JSON API: Consented web search transmits your query. Deprecation Notice: Closed to new customers on January 20, 2026, and scheduled for discontinuation/sunset on January 1, 2027. Governed by the Google APIs Terms of Service (which permit API quality monitoring and security/service processing) together with the general Google Privacy Policy on global Google servers. Qualification: Published Google timeframes such as 9-month IP anonymization and 18-month cookie anonymization describe advertising server logs under Google's general privacy policy rather than an API-specific query-log retention commitment; exact Custom Search JSON API server-log retention days and regional pinning options are not published publicly.
  • Serper (serper.dev): Consented web search transmits your query. Governed by Serper Terms of Service and Privacy Policy. Serper queries Google sources in real time, explicitly states it does not cache search results, does not indicate user API queries are used for AI model training, and retains account and billing records while an account is active or required by law. Unavailable details: exact server hosting regions and exact ephemeral API query-log purge periods are not published publicly.
  • DuckDuckGo: Chosen or fallback search queries use an open-source third-party library connecting to public DuckDuckGo endpoints rather than an official enterprise developer API or DPA. Under DuckDuckGo's general Privacy Policy, DuckDuckGo states it does not save or share search or browsing history tied to IP addresses or unique identifiers, retains only anonymous aggregate statistics, and proxies queries to search partners (including Microsoft Bing) without sharing user IPs or personal data. Unavailable details: exact edge datacenter locations and ephemeral CDN log rotation windows are not published publicly.
  • Microsoft Bing Web Fallback: Fallback search queries Bing's public web search page rather than an enterprise Azure Bing Search API agreement (Microsoft DPA / Online Services Terms). Governed by Microsoft's general consumer Privacy Statement, under which Microsoft states Bing search queries are separated from account identity and full IP addresses are deleted after 6 months (no enterprise API ZDR SLA applies to unauthenticated web fallback).
  • Visited Public Websites: Opening a pasted web address or fetching full article pages from search results sends the requested web address, your IP address, and browser user-agent metadata directly to the destination website operator under that site's own privacy policy and hosting regions, which vary per domain and cannot be pre-verified.
  • YouTube: Submitting a YouTube video or song link sends the requested video identifier to YouTube under YouTube Terms of Service and the general Google Privacy Policy across global Google servers. Qualification: Google's general 9-month IP / 18-month cookie anonymization rule covers advertising server logs rather than providing a specific retention guarantee for unauthenticated YouTube metadata, transcript, or media requests; exact retention periods for those requests are not published publicly.
  • Ollama Model Registry & CDN: Pulling optional local AI models sends requested model identifiers and standard HTTP request metadata (including IP address; primary United States infrastructure and global Cloudflare CDN) under the Ollama Privacy Policy, without transmitting your local chat messages. Distinction: Ollama's published Zero Data Retention and zero-training commitments apply to Ollama Cloud inference rather than local model downloads; exact registry and CDN HTTP access-log purge days are not published publicly.
  • GitHub (Optional Standalone Runtime Download & Privacy Website Host): In standalone desktop installers (disabled in Microsoft Store builds), explicitly choosing to download Ollama sends installer download requests to GitHub Releases. Viewing a privacy webpage hosted on GitHub Pages also falls under the GitHub General Privacy Statement; GitHub Pages documentation states that visitor IP addresses are logged and stored for security purposes even when signed out. Exact HTTP server log retention periods are not published publicly.
  • Gmail Support Mailbox: Voluntarily emailing ruflow.support@gmail.com transmits your email message and any attachments through Google's mail servers under Google Terms of Service & Privacy Policy. Support mailbox retention is separately administered by the developer.

5. Per-Provider Consent, Fallbacks & Revocation

  • Separate Consent per Feature and Provider: Before transmitting web search queries, pasted website links, YouTube links, topic news lookups, deep research queries, or Research Sheets queries externally, RuFlow requests explicit permission keyed separately by both feature and external provider. Local Ollama conversations and local file processing never prompt for external consent.
  • Allow Once, Allow & Remember, or Decline: On first use, you choose Allow Once, Allow & Remember, or skip external lookup altogether.
  • Separate Consent for Full Webpage Reading: Approving a search engine provider for search result snippets never authorizes fetching full article webpages returned in search results; full-page fetching requires separate explicit approval.
  • Mandatory Fresh Consent for Fallback Providers: Consent remembered for a primary search engine never applies to fallback providers (such as DuckDuckGo or Bing fallback search). Fallback providers always require fresh one-time permission and are not persistently remembered.
  • Revocation Controls: You can revoke remembered permissions individually or click Revoke All External Consents anytime under Settings -> Privacy, Consent & Cleanup and in Research Sheets controls.

6. Canva Integration (Packaged Status & API Terms)

  • Packaged Release Status: Canva integration is optional, switched off by default, and live Canva connections cannot execute in the standard core Windows desktop package because Canva's external connection client library is omitted from the core installer.
  • Authentication & Data Protection (When Separately Provisioned): Where optional Canva support is separately installed and enabled by you, sign-in uses OAuth with PKCE over a temporary local loopback callback on your PC, requesting read permissions by default (profile, design metadata, design content, folders, and assets) and write access only when requested. Authorization tokens are stored encrypted locally on your Windows account via Windows Data Protection (DPAPI) and Windows Credential Manager, and clicking Disconnect Canva clears stored local encrypted tokens and session data.
  • Canva Governance & Limits: API calls are governed by Canva's API and App Developer Terms (Schedule 1) and DPA separately from Canva's general consumer Privacy Policy. Developer Terms limit retention of API inputs/outputs strictly to providing, maintaining, and securing the API service and prohibit using Canva API content or outputs to train AI models; programmatic export download links expire after 24 hours; enterprise accounts support regional data residency options (such as US or EU); exact consumer API audit-log retention periods are not published publicly.

7. Deleting Local Data: In-App Controls vs. Manual Action

Because RuFlow stores your workspace on your own computer, some categories can be deleted inside RuFlow while others require manual action in Windows or Ollama:

Data You Can Delete Using RuFlow's UI

  • Conversations & Messages: Delete an entire conversation from the sidebar or individual prompt/reply pairs inside chat (deletes local database history only and never deletes files on disk).
  • Favorites & Staged Chat Inputs: Remove starred favorites or click Clear on pending attachments before sending.
  • Unreferenced Managed Chat Attachment Copies: In Settings -> Privacy, Consent & Cleanup -> Orphan Chat Attachment Cleanup, run a read-only scan of managed copies no longer linked to any conversation, inspect the preview list, and confirm deletion explicitly. Personal uploaded folders, custom files, shared attachments still linked to another chat, and symbolic links are never treated as orphans or deleted automatically.
  • Remembered External Provider Approvals: Revoke individual permissions or click Revoke All External Consents in Settings -> Privacy, Consent & Cleanup (and Research Sheets controls).
  • Research Sheets & Rows: Delete individual Research Sheets or delete table rows directly inside the Research Sheets page.
  • Saved AI Concern Report Drafts: Delete individual locally saved drafts with confirmation inside Report AI Content.
  • Saved Sing Voice Recordings: Delete individual saved voice takes with Delete recording on the Sing page.
  • Active Video Job Cards: Dismiss queued or completed video job entries from the active session view.

Data Requiring Manual User Action Outside RuFlow

  • Diagnostic & Operational Log Files: No UI button deletes log files; remove them manually from your Windows user profile's RuFlow logs folder if desired.
  • Uploaded Documents & Saved Exports: Files in RuFlow's uploads folder and documents/presentations exported to your computer remain on disk until deleted manually in Windows Explorer.
  • Locally Installed Ollama AI Models: Remove or uninstall downloaded AI models directly through Ollama's own commands or model storage tools.
  • Application Settings, Knowledge Indexes & Residual Workspace Folders: Removing all preferences, local textbook databases, task history, and residual profile files requires manually deleting your RuFlow folder under your Windows user profile's local application data directory (uninstalling or updating RuFlow does not automatically delete external local user data).

8. Data Retention: Current Practice, Proposed Rules & Support Mailbox

  • Current Application Behavior: No automatic time-based retention deletion or background pruning is active in RuFlow today. Local chats, logs, uploaded documents, settings, and temporary local AI concern drafts stay on your PC until removed via UI controls or manually by you.
  • Proposed Application Retention Targets (Not Yet Implemented or Active):
    • Local Diagnostic Logs: Proposed maximum retention 30 days.
    • Local Temporary AI Concern Report Drafts: Proposed maximum retention 90 days — strictly excluding documents you have explicitly saved or exported.
    • User Chats, Saved/Exported Documents & Installed Models: Remain under your control indefinitely with no automatic deletion.
  • Support Mailbox Retention (ruflow.support@gmail.com) — Separately Administered by the Developer: Support emails and attached reports reside in the developer's Gmail support mailbox rather than inside the RuFlow application, so retention and deletion there are separately administered by the developer under Google mail terms (with mailbox access restricted to the application owner initially). Under proposed administrative policy, closed support threads are targeted for manual review or deletion up to 180 days after issue closure, subject to applicable legal obligations.
